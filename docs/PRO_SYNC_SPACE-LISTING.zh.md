## 一句话

Pro 会员可以**显式开通**一个「独立同步空间」（一个独立数据库），把某个 vault 的同步放到
这个空间里；它不会自动改变你现有 vault 的同步行为，普通用户与会员的同步行为也完全不变。

---

## 两条现在就要说清的边界

**一、独立空间目前只隔离「客户端设备之间」的同步，服务端 AI 不读它。**

Pro 独立同步空间当前只解决客户端设备之间的同步隔离：多台设备指向同一个空间，数据就互不串。
但服务端的 AI 任务 / agent 暂时**不读取**这个空间的内容——把 vault 放进独立空间后，
AI 相关能力仍然看不到里面的笔记。这项能力尚未实现，上线前会补上；在此之前，请不要把
「开通独立空间」理解成「空间里的内容自动接入 AI」。

**二、旧卡密开通独立空间，会换一把新口令，相当于把现有 vault 重新上传一次。**

如果你用的是已经在使用中的旧卡密（legacy 明文租户），开通独立空间时会为这个新空间生成一把
**新的内容加密口令**，它与旧空间的口令不通用。所以把现有 vault 迁进独立空间，效果等同于
**向新空间重新上传一次**，而不是原地换一个库；旧空间里的数据原样保留、不会被删除，
你随时可以切回旧空间继续使用。

---

## 包含什么（已确认口径）

- **Pro 会员专属**：基础版与会员不可开通。
- **独立同步空间 = 独立数据库**：用于承载指定 vault 的 LiveSync 同步数据，与默认同步空间隔离。
- **生命周期**：Pro 有效期内该空间可读写；到期/退订后**只读保留**（数据保留，不删除）；
  续费后恢复写入。
- **隔离的是空间，不是身份**：账号、登录方式、卡密激活流程都不变；被隔离的是同步空间（数据库）。
- **显式开通**：只有你主动开通，才会为你建立/绑定这个空间；不自动生效。

## 不包含什么

- **不改变账号身份**：不新增账号，不改变登录/卡密/激活流程。
- **不自动迁移既有数据**：不会因为升级、续费或开通动作而悄悄替换你现有 vault 的同步目标。
- **不影响其它用户**：基础版、会员、以及**未开通**该空间的 Pro 用户，同步行为完全不变。
- **不替代 Pro 的其它权益**：优先队列、Cloud-Vault 云端备份、更多设备数等按各自规则提供，
  以账户页权益摘要为准。
- **不承诺共享/协作**：多人共写同一空间的能力未定义。
- **不承诺口令找回**：E2EE 口令仍在你的设备与激活链路，服务端不代为保管或找回。

## 如何开通（已确认：显式开通；入口待验证）

- 已确认：**必须显式开通，不会自动生效**。
- 待验证：
  - 插件内具体入口（账户页 / 同步设置页 / 客服工单）与二次确认流程；
  - 开通是否需要服务端先建库并绑定租户、配额，以及是否幂等；
  - 开通是否占用或消耗会员权益、是否有额外计费。

## 如何把现有 vault 迁入（待验证，方向性描述）

意图方向：先开通空间 → 在客户端把它选为该 vault 的目标同步空间 → 触发一次全量同步。

以下**全部待验证**，上线前不得对买家承诺任何细节：

- 迁移是「客户端切换目标 + 全量复制」，还是由服务端/运维代迁；
- 迁移期间的冲突策略、断点续传与进度提示；
- 是否需要先备份、是否需要暂停其它设备；
- 迁移完成后原空间数据是否保留（预期保留，待确认）。

## 能否迁回（待验证）

- 是否支持把该 vault 切回原空间；
- 切回是增量同步还是重新全量同步；
- 迁回是否自动、是否会产生副本、如何处理两个空间期间的并发改动。

## 降级后行为（已确认口径 + 待验证强制点）

- 已确认：Pro 到期/退订后，该空间**只读保留**，续费后恢复写入；数据不删除。
- **待验证（关键）**：只读必须是**服务端 / CouchDB 层强制**（写请求被拒绝），而不是仅靠客户端
  界面限制。在这一点通过验收前，不得宣称「到期后一定写不进去」。
- 待验证：只读期间设备端表现（错误提示、是否自动降级为本地只读、续费后的追平行为）。

## 与各档位的关系

| 档位 | 既有同步行为 | 独立同步空间 |
|---|---|---|
| 基础版 | 不变 | 不可开通 |
| 会员 | 不变 | 不可开通 |
| Pro（未开通空间） | 不变 | 不生效 |
| Pro（已开通空间） | 不变 | 额外可用，按上述生命周期 |

## 与 Cloud-Vault 的区别（避免混淆）

- **Cloud-Vault**（已有 Pro 权益）：把 vault 备份到云端对象存储，属于**备份 / 恢复**。
- **独立同步空间**：LiveSync 的**同步目标数据库**，属于**多设备同步的落点**。

两者是不同能力，不要混为一谈。

## 上线前仍需验证（诚实清单）

1. **权益字段与强制点**：后端 `Entitlements` 增加 Pro 专属字段，并在每个消费点做服务端判定
   （当前 `app/plans.py` 无此字段，属于「仅下发/未强制」阶段）。
2. **独立数据库生命周期**：创建、绑定租户、命名规则、配额、退订后的保留与清理策略。
3. **降级只读的服务端强制**：CouchDB `_security` / 只读账号，而非仅客户端 UI。
4. **开通流程**：入口、前置校验（档位、设备数）、幂等与失败回滚。
5. **迁入 / 迁回**：端到端流程、冲突策略、断点续传、并发设备处理。
6. **计费联动**：退订/续费/退款与空间只读/恢复的时序，是否需要宽限期。
7. **多设备一致性**：一台设备开通后，其它设备的可见性与切换体验。
8. **客户端呈现**：i18n、错误文案、账户页权益状态展示。
9. **发布前门禁**：为本能力补一条 `setup URI → 目标数据库 → 真实 GET` 的端到端用例并纳入
   每次切版（可复用 `docs/osyc-sync-acceptance.zh.md` 的门禁框架）。
